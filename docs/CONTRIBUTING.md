# Contributing to DevEnvTemplate

Thanks for helping improve the doctor! This repo is meant to be vendored inside other projects, so we keep the editing workflow predictable:

## Build + test loop

1. `npm install`
2. `npm run build` – this automatically runs `tsc --noEmit` **before** compiling to `dist/`. Fix any type errors before moving on.
3. `npm run test:unit` or `npm run test` – every test command rebuilds first and then executes against the freshly emitted `dist/scripts/**` files (the same code shipped to users).
4. Run targeted tools for smoke testing, e.g.:
   - `node dist/scripts/tools/stack-detector.js --json`
   - `node dist/scripts/tools/gap-analyzer.js`
   - `npm run doctor` inside `.devenv/`

Why this flow?

- The `.devenv` folder that gets vendored into other repos only contains the **dist** output.
- Tests exercising the compiled files ensure we never rely on TypeScript-only features at runtime.
- Rebuilding before tests guarantees `dist/` never drifts from `scripts/**/*.ts`.

## Editing rules

- Put all substantive logic in TypeScript (`scripts/**/.ts`). `.js` files in this repo are thin wrappers that import from `dist/` for backwards compatibility or one-off bootstrap scripts such as `ensure-gitignore`.
- Never edit files in `dist/`. They are generated by `npm run build`.
- If you need new fixtures or sample projects, add them under `tests/fixtures/` so doctor changes stay regression-tested.

## Running in development

- Use `npm run build:watch` during local development to keep `dist/` in sync while editing TypeScript sources.
- When debugging stack detection against a real project, run `node dist/scripts/tools/stack-detector.js --json` from inside that project’s `.devenv/` directory. The CLI auto-detects the parent repo.

That’s it—stay in TypeScript, keep `dist/` fresh, and the embedded doctor will behave exactly like your local build.
